# Encode the selected movement in the URL

## Ask

Rewrite the URL to encode the currently selected movement

## Answer

The selected movement is now kept in a `movement` URL parameter, written as
`<artist id>/<work id>/<movement id>`. For example:
`index.html?movement=anlun-huang/chinese-requiem/ch2`.

Changes in `app.js`:

- New section MOVEMENT IN URL:
  - `setMovementInUrl(movement)` rewrites the URL with `history.replaceState`. It
    keeps the other parameters and the `#hash`, and adds no history entry.
  - `movementFromUrl()` finds the movement the parameter names. If none matches, it
    logs a console warning.
- `loadMovement()` calls `setMovementInUrl()`, so the URL changes on a tree click,
  Prev/Next, and auto-advance.
- `selectFirstMovement()` is renamed `selectInitialMovement()`. On load it selects
  the movement from the URL. If there is none, or it is unknown, it falls back to the
  first movement in the tree. Either way it opens that movement's folders.

`README.md` has a new `movement` row in the URL-parameters table.

Verified in headless Chrome on file://:

- Plain load gives `?movement=anlun-huang/chinese-requiem/ch1`.
- Next, then a tree click, update the URL, and `history.length` stays the same.
- Loading with `...&movement=anlun-huang/chinese-requiem/ch5` opens Ch. V with its
  folders open, and `highlight-mode` and the colors still apply. A reload keeps Ch. V.
- An unknown key falls back to Ch. I and rewrites the URL.
- `%2F`-encoded slashes are accepted, and a `#hash` is kept.

One side effect: other parameters get re-encoded when the URL is rewritten. For
example, `rgba(0,0,0,0.2)` becomes `rgba%280%2C0%2C0%2C0.2%29`. The value is the same.
